Implementation
- Binary xterm events use a separate byte-valued API, Latin-1 -> canonical base64 -> Buffer, and the same PTY as Unicode text.
- Additive binary-input-v1 capability keeps protocol version 2. Old/live daemons continue text service and return false for binary; no fallback encoding and no restart for this feature. Old clients ignore the new ready field.
- Main input serializes text/binary around agent wake, bounds retained input (512,000 bytes / 1,024 calls), and invalidates stale work on detach/dispose/disconnect. Binary reports are capped at 16,384 bytes; socket queue/frame limits remain enforced.
- Terminal-local capture handles only LINE/PAGE with signed residue, reversal/unit/buffer resets, rows-1 page cap, and Alt x5 once. Alternate screen without tracking uses public input with bounded CSI/SS3 repetitions. Pixel input and application tracking are delegated unchanged.
- No sensitivity preference, automatic device classifier, coordinate packet generation, forced SGR, private xterm core API, or global wheel hook.
