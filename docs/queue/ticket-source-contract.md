# Ticket queue contract (SUP-39 / own-ticket SUP-42)

Identity is provider + authenticated account + provider site + immutable ticket identity. Linear uses its account UUID and issue UUID; Jira uses cloud ID, account ID and issue key. A queue source is global to that identity, regardless of which folder, repository or orchestrator is open. Project/workspace context comes only from an explicit, identity-scoped link; names and current cwd never route an action.

Intake includes tickets assigned to the authenticated account, in Linear `unstarted` or Jira `new`, without a verified link. The first complete account snapshot is silent. A later eligibility transition appears, including a newly assigned ticket. Show all my unstarted tickets deliberately includes the baseline. Title, description and display-name edits never increment receipts. Open is navigation only; Start opens the existing branch confirmation flow. A successful link immediately resolves intake; a failed creation or link does not.

Own-ticket feedback means a ticket currently assigned to this account and already started or explicitly linked. New comments by another identified author, including comments mentioning the owner, require reading/replying. Assignment changes and unauthored status snapshots are not feedback. This initial contract intentionally excludes status-change events: the existing providers do not expose an attributable status event stream, so inferring one would invent who needs a response. Each ticket establishes a silent comment baseline when it first becomes owned work. Comment IDs are occurrences; edits to an already seen comment are metadata only. An unknown author is not admitted because self-suppression cannot be proven.

A later self-authored comment resolves earlier feedback only when its provider timestamp is strictly later than every pending external comment. Opening, starting a local task, or merely polling never resolves feedback. Explicit Done dismisses the exact revision. A new external comment after Done/Later creates a new revision. A complete provider snapshot confirming reassignment/closure resolves the occurrence. Failed/incomplete list or comment reads retain the last verified candidate and mark it unavailable. Successful empty snapshots are distinct from absent caches.

Queue reads use fresh provider snapshots independent of Tickets tab filters and legacy cache. Account/site changes hide old sources; replies to an old account can never clear the current account. Legacy Jira links have no site proof and cannot resolve or route a queue source; new links record account/site provenance. No external writes are performed by this adapter.
